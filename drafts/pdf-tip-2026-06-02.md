Document Accessibility Tip of the Day

📃Topic: Tables: header cells, scope, and structure📄

Data tables in PDFs only work for screen reader users when the row and column relationships are machine-readable, not just visually obvious. Getting the tag structure right is what lets assistive technology announce the correct header when a user lands in any data cell.

In Acrobat Pro's Tags panel, every header cell should be tagged <TH> (not <TD>), and each <TH> needs a Scope attribute — Column for cells at the top of a column, Row for cells at the start of a row, and Both when a corner cell heads both a column and a row.

The table itself should be a clean <Table> > <TR> > <TH>/<TD> hierarchy with no stray <P> or <Span> wrappers in between, and merged cells need ColSpan or RowSpan set so a screen reader announces the right header when a user lands in a data cell.

For tables with two levels of headers (for example, a year row above quarter rows), use the Headers/ID attributes to point each data cell at the specific header IDs that describe it, since Scope alone can't disambiguate the relationship.

Avoid using tables purely for visual layout — if it isn't really tabular data, retag it as paragraphs or a list so assistive technology doesn't announce phantom rows and columns.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.5 in your ISO 14289-1 copy.
