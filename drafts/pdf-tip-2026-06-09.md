Document Accessibility Tip of the Day

📃Topic: Running headers and footers belong in the artifact layer, not the reading order📄

Page numbers, document titles, chapter names, and other running content that repeats across every page exist for sighted navigation in a paginated layout — they are not part of the document's narrative. When those repeating elements are left in the tagged content tree, a screen reader interrupts the body of the document on every single page to announce "Annual Report 2026 — page 4 of 38" before continuing the sentence it was reading. The fix is to move that recurring furniture out of the reading order entirely and mark it as pagination artifact.

In Acrobat's Tags panel, running headers and footers should not appear as P, Span, or any other structure tag. Instead, they belong in the artifact layer with an artifact subtype of Pagination. You can confirm this from the Content panel — each header and footer object should sit inside an Artifact container, not under a tagged structure element. If you find them tagged, the cleanest fix is to use the Touch Up Reading Order tool to select the header and footer regions on a representative page and apply Background/Artifact, then verify with the Order panel that the body text now flows uninterrupted from one page to the next.

A few things commonly trip this up. First, a logo or agency seal that sits inside the header region is still an image and may carry meaning — decide once whether it conveys information (tag it as a Figure with alt text, in the body's reading order, not in the header) or is purely decorative (artifact it along with the rest of the header). Second, if the same header and footer were inserted differently on the first page, on section dividers, or on rotated landscape pages, check each variant — artifacting page 1 does not artifact page 2. Third, watermarks behave the same way: a "DRAFT" or "CONFIDENTIAL" stamp that repeats on every page should be a pagination or layout artifact, not announced as content on every page.

The payoff is concrete. A screen reader user can move from page to page without the announcement of page numbers and section titles drowning out the actual document, and an AT user navigating by structure can rely on the tag tree as a faithful map of the content rather than a tree cluttered with repeating chrome. If page numbers still matter for citation, they remain available through the Pages panel and the page label metadata — artifacting the visible header does not remove that affordance, it just stops the header from being read aloud.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.8 in your ISO 14289-1 copy.
