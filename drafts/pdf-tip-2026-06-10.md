Document Accessibility Tip of the Day

📃Topic: Write meaningful link text in Word so the exported PDF has usable links📄

When a reader uses a screen reader, the tool can pull every link out of the document into a single navigable list. If that list is full of bare URLs like "https://example.gov/sites/default/files/2024-budget-final-v3.pdf" or a stack of identical "click here" entries, the list is unusable — there is no way to tell one link from another out of context.

In Word, fix this at authoring time instead of repairing it later in the PDF. Select the words you actually want the reader to act on, then use Insert > Link (or Ctrl+K) and put the destination URL in the Address field while leaving descriptive words in the Text to display field. Aim for text that names the destination on its own: "2024 adopted budget (PDF)" rather than "click here for the budget," and the department or page title rather than the full URL.

This pays off in two places. The exported PDF carries your display text into the Link tag's contents, so the screen reader's list of links reads as a meaningful table of contents instead of a wall of URLs. It also means a remediator does not have to open every Link tag later and add an alternate description by hand to make the link self-describing — the document is already accessible on export.

One more habit worth building: if the same words link to two different destinations in one document (for example, two different "Annual Report" links), differentiate them in the visible text itself ("2024 Annual Report," "2025 Annual Report") so a reader skimming the link list can tell them apart.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.18 in your ISO 14289-1 copy.
