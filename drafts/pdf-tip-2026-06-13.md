Document Accessibility Tip of the Day

📃Topic: Embedded files and attachments📄

A PDF can carry other files inside it — a spreadsheet, a second PDF, a CSV, an image — and these embedded attachments are easy to overlook during remediation. Assistive technology users need to be able to discover them, understand what each one is, and decide whether to open it, just like any sighted user clicking the paperclip panel.

When you attach a file in Acrobat Pro, give it a clear filename that reflects its content, and fill in the Description field on the attachment's properties. The description is what a screen reader announces, so "Q3 budget appendix, Excel spreadsheet, 42 KB" is far more useful than the bare filename. If the attachment exists only to provide an alternate version of something already in the PDF (for example, a CSV of a table that is also tagged inline), say so in the description so users know they have a choice and are not missing content.

Attachments should also be reachable. Confirm the PDF opens with the Attachments panel visible or easy to find — in Acrobat, set the Initial View to show the Attachments panel when attachments are present, or at least leave the Navigation pane unlocked so the user can open it. If an attachment is itself a PDF, that inner PDF needs to be tagged and accessible on its own; embedding does not inherit the parent's accessibility.

Finally, do not use attachments as a substitute for accessible content. If the body of the PDF is an untagged scan and the "accessible version" is an attached Word file, the PDF itself still fails. The attachment is supplementary; the host document still has to stand on its own.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.11 in your ISO 14289-1 copy.
