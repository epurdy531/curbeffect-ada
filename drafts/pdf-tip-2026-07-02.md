Document Accessibility Tip of the Day

📃Topic: Checking and fixing logical reading order in a tagged PDF📄

Tagging your content is only half the job. A PDF can have a heading tag, paragraph tags, and a figure tag and still read back as nonsense, because the order the screen reader follows is the order of the tags in the tag tree — not the order things appear on the page. Multi-column layouts, sidebars, pull quotes, and captions are where this goes wrong most often.

After you've tagged a document in Acrobat, open the Tags panel and walk the tree from top to bottom. Read it as a story: does the first-column text finish before the second column starts, or does the tree jump across columns mid-sentence? A common failure is a caption or a boxed callout landing in the middle of the body text because that's where it sits visually. Drag tags within the tree to put them in true reading sequence.

The fastest way to hear the problem is Acrobat's Reflow view (View ▸ Zoom ▸ Reflow). Reflow collapses the page to a single column and follows the tag order exactly, so a sidebar that jumps into the body, or a two-column page that reads straight across, becomes obvious immediately. Fix the tag order, reflow again, and confirm it reads cleanly.

One caution: the Order panel (the "Order" or content-order view) controls a different thing — the sequence content is painted and how the Reading Order tool numbers regions — and it does not always match the tag tree that assistive technology actually follows. When the two disagree, trust and correct the Tags tree, then re-test with Reflow or a screen reader.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.1 in your ISO 14289-1 copy.
