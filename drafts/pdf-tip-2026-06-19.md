Document Accessibility Tip of the Day

📃Topic: Links and their alternate descriptions📄

A link in a PDF is more than a clickable rectangle on the page — for assistive technology, it has to be a real Link tag in the structure tree, wrapping the visible text the user reads, and pointing to an action a screen reader can announce. When any of those three pieces is missing, the link is either invisible to AT or shows up as a stray URL with no context.

In Acrobat Pro, open the Tags panel and confirm that each link is wrapped in a Link tag that contains both the visible link text and a Link - OBJR entry referencing the link annotation. If the link text is generic — "click here," "read more," or a bare URL — give the annotation an Alternate Description in its Properties dialog that says where the link actually goes, for example "CurbEffect accessibility services page." Screen readers will announce that alternate description instead of the raw text, so a user pulling up a list of links on the page gets a meaningful destination for each one.

A few habits keep link remediation quick. Make sure the Link tag wraps the entire phrase that should be clickable, not just one word in the middle. Do not nest Link tags inside other Link tags. And when the same URL appears more than once on a page, give each instance an alt description that distinguishes them rather than leaving identical "Learn more" links the user cannot tell apart.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.18 in your ISO 14289-1 copy.
