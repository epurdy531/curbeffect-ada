Document Accessibility Tip of the Day

📃Topic: Keep Word tables simple — repeat the header row and skip merged cells📄

When you build a data table in Word, designating a header row is only half the job. The way you structure the rest of the table decides how much cleanup the exported PDF will need — and complex tables are where remediation time disappears.

Keep every data table a plain grid: one header row, then consistent data rows with one piece of information per cell. Avoid merged or split cells, nested tables, and blank cells used for spacing. Each of those breaks the row-and-column relationship that a screen reader relies on, and in the PDF it turns into spanned cells and orphaned content you have to retag by hand. If your data really needs a merged cell, that is usually a sign the information should be two simpler tables instead of one complicated one.

When a table runs longer than a page, select the header row, open Table Layout, and turn on "Repeat Header Rows." Word will reprint that header at the top of each page, and on export those repeated rows are marked as headers rather than as new data — so a reader who lands on page three still knows what each column means.

Finally, never use a table just to position text or images side by side. Layout tables export as real table structure, forcing assistive technology to announce rows and columns that carry no meaning. Use Word's columns, text alignment, or a borderless layout instead, and reserve real tables for actual tabular data.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.5 in your ISO 14289-1 copy.
