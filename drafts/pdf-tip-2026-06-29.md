Document Accessibility Tip of the Day

📃Topic: Security settings that keep assistive technology access open📄

A PDF can be perfectly tagged and still be unusable for someone relying on a screen reader if the wrong security setting is switched on. When you password-protect or encrypt a document, watch the permissions you grant — one of them controls whether assistive technology is allowed to read the content at all.

In Acrobat Pro, open File ▸ Properties ▸ Security. If the document uses Password Security, look at the permissions and make sure "Enable text access for screen reader devices for the visually impaired" stays checked. That checkbox is easy to miss because it sits alongside printing and editing permissions, and older tools sometimes cleared it by default. With it turned off, a screen reader is blocked from extracting the text even when every heading, list, and image is tagged correctly.

The safest habit is to avoid restrictive encryption on public-facing documents in the first place. A city posting a meeting agenda or a budget rarely needs to lock down copying or editing, and those restrictions add nothing but risk for accessibility. If a document must be secured, choose a method that explicitly preserves content extraction for accessibility, then test it with a screen reader before publishing.

When you remediate a file that arrived already encrypted, check the Security tab before you do anything else. Re-tagging a locked document wastes effort if assistive technology still can't reach the text — clear or correct the security settings first, confirm the screen-reader permission is open, and then verify the structure.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.16 in your ISO 14289-1 copy.
