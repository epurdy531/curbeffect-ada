Document Accessibility Tip of the Day

📃Topic: Document Metadata, Title, and DisplayDocTitle📄

A finished PDF can have perfect tags and still announce itself by its file name. When a screen reader user opens a document, the first thing they hear in the window title is usually whatever sits in the file's title field — and if that field is empty, assistive technology falls back to the file name, so they hear something like "Report_FINAL_v3.pdf" instead of "2026 Annual Budget Report." Setting a real, human-readable title is one of the quickest, highest-impact fixes in remediation.

In Acrobat Pro, open File ▸ Properties ▸ Description and type a clear, descriptive title in the Title field — write it the way you'd want it read aloud, not the way the file is named on disk. While you're there, fill in the language if it isn't already set. The title field alone, though, is not enough: a PDF carries a separate switch that decides whether the viewer shows that title or the file name in the window bar.

That switch is DisplayDocTitle, and it must be turned on for the title to actually be used. In Acrobat, go to File ▸ Properties ▸ Initial View and set "Show" to "Document Title" instead of "File Name." Without this, you can have a beautifully written title that no one ever hears, because the viewer keeps displaying the file name regardless.

After setting both, verify the result: close and reopen the file and confirm the window or tab shows your descriptive title rather than the file name. This pair — a meaningful title plus DisplayDocTitle enabled — is checked by automated tools and is one of the first things an auditor looks for, so make it a standing item on your remediation checklist.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.1 in your ISO 14289-1 copy.
