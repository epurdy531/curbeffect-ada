Document Accessibility Tip of the Day

📃Topic: Making sure the "text" in a PDF is really text📄

Before you worry about tags or reading order, confirm the page actually contains extractable text and not a picture of text. A scanned memo or a flyer exported from a design tool can look perfect on screen while a screen reader finds nothing to read.

The fastest check is to open the PDF, press Ctrl+A to select all, and try to copy a sentence into a text editor. If nothing highlights, or you get gibberish, the words are living inside an image and no amount of tagging will fix that. Run Acrobat's Scan & OCR tool ("Recognize Text") to convert those image pages into real characters, then re-check by copying again.

Even when text selects cleanly, the underlying character mapping can still be wrong. Copy a paragraph that includes numbers, quotation marks, or accented letters and paste it somewhere plain. If "ﬁ" comes out empty, quotes turn into boxes, or ligatures drop letters, the font is missing a correct Unicode (ToUnicode) mapping — a screen reader will announce the same garbage a user just pasted. Re-running OCR or re-exporting from a properly embedded font usually restores it.

Only after the page is genuinely text should you declare the document's natural language, so assistive technology pronounces it correctly. In Acrobat, set File ▸ Properties ▸ Advanced ▸ Reading Options ▸ Language for the whole document, and override any passage in another language on its tag. Real text plus a stated language is the foundation everything else in remediation is built on.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.2 in your ISO 14289-1 copy.
