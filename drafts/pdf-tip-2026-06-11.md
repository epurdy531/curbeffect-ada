Document Accessibility Tip of the Day

📃Topic: Footnotes, endnotes, and references in tagged PDFs📄

Footnotes and endnotes are easy to get wrong because they look like ordinary text on the page, but to a screen reader user they only make sense when the reference marker, the note body, and the surrounding paragraph are connected as structure rather than just visually positioned near each other.

In the tag tree, the small superscript reference in the body should be wrapped in a Reference tag (Tag type Reference, often abbreviated Ref) so assistive technology announces it as a reference and not as a stray number jammed into a word. The footnote itself, sitting at the bottom of the page or in a notes section at the end, belongs in a Note tag with its own identifier. Each Note should have an ID set on it, and the in-text Reference should point to that ID so a user can jump from the marker to the note and back without losing their place in the reading order.

A few things to check when remediating: confirm the Reference tag sits inside the parent paragraph at the exact spot the marker appears, so reading order is uninterrupted; confirm the Note tag is not buried inside the running paragraph, since that pulls the entire footnote into the middle of the body when read aloud; and confirm the IDs are unique across the document. For endnotes and bibliographies, the same pattern applies — references in the text point to Note entries collected at the end, and any URLs inside those entries should be wrapped in Link tags with meaningful alternate text rather than left as raw underlined strings.

If the source document was authored in Word and the footnotes were inserted with the References tool, much of this structure carries through on export and only needs verification. If the footnotes were typed by hand as superscripts and a separate paragraph at the bottom of the page, expect to rebuild the connection in the tag tree manually.

🔍 Reference: for the exact normative wording, see PDF/UA clause 7.9 in your ISO 14289-1 copy.
